## Base URL

```text
https://api.dexbuilder.com
```

## REST 路由與身分

| 類型 | 路徑前綴 |
| --- | --- |
| 公開行情路徑 | `/api/v4/event_contracts` |
| Broker 代使用者路徑 | `/api/v4/broker/event_contracts` |

公開市場資料維持原路徑，無須 Broker Key；訂單、持倉、帳戶及結算等私有介面使用 Broker 路徑。私有請求必須攜帶 Broker API Key、簽名和 `sub_user_wallet_addr`，閘道會驗證錢包屬於目前 Broker。 詳見[Broker API 認證與簽名](/zh-TW/event-contracts/api/broker-authentication)。

## 介面存取模型

| 介面類型 | 是否需要認證 | 典型能力 |
| --- | --- | --- |
| 市場發現 | 否 | 事件、市場、標籤 |
| 市場資料 | 否 | 價格、Ticker、訂單簿、歷史資料、K 線 |
| 交易 | 是 | 下單、查詢訂單、撤單 |
| 帳戶 | 是 | 持倉、資產、餘額、費率、個人成交 |
| 結算 | 是 | 平倉、領取、資金處理 |

## 分頁

清單介面使用游標分頁，回傳 `items` 與 `next_cursor`。下一頁請求直接使用上一頁回傳的 `next_cursor`，不要自行解析或修改游標。

## 時間與數值約定

- 事件與市場日期欄位通常使用 Unix 秒；
- `from`、`to` 等範圍參數通常使用 Unix 毫秒；
- 價格、數量、成交額、餘額、手續費等金額類欄位通常以字串回傳，建議使用 Decimal 精度處理。

## 標準錯誤

```json
{"label":"INVALID_ARGUMENT","message":"invalid request"}
```

常見 HTTP 狀態包括 `400`、`401`、`404` 和 `503`。
