---

事件合約的公開行情介面維持 `/api/v4/event_contracts/...` 路徑，無須 Broker API Key。Broker 代使用者執行訂單、持倉和帳戶等私有操作時，使用 `/api/v4/broker/event_contracts/...`，並提供目標使用者的錢包地址。

## 取得與使用 Broker API Key

透過專案方管理流程申請或建立目前 Broker 專用的 API Key，並開通事件合約對應權限。讀取操作需要唯讀或讀寫權限；寫入操作需要讀寫權限。建立後安全保存 `Key` 和 `Secret Key`。終端使用者的個人 API Key 不能代替 Broker API Key。

| Header | 要求 |
| --- | --- |
| `KEY` | Broker API Key |
| `Timestamp` | 目前 Unix 秒級時間戳，與閘道時間差不超過 60 秒 |
| `SIGN` | 使用 Secret Key 產生的 HMAC-SHA512 十六進位簽名 |
| `sub_user_wallet_addr` | 目標終端使用者的錢包地址，本節所有 Broker 私有 REST 介面皆必填 |

閘道從 Broker API Key 確認 Broker 身分，驗證錢包與該 Broker 的綁定關係。驗證通過後，才會以對應使用者身分轉發。錢包未綁定或不屬於目前 Broker 時，請求會遭拒絕。客戶端無須傳入使用者 UID 或閘道內部身分 Header。

## HTTP 簽名

依序以換行符號連接大寫 HTTP 方法、實際外部請求路徑、實際傳送的 Query String、請求 Body 原文的 SHA512 十六進位摘要，以及 `Timestamp`；無 Query 或 Body 時使用空字串對應的值。接著計算 `SIGN = HexEncode(HMAC_SHA512(Secret Key, 簽名原文))`。

```text
HTTP_METHOD + "\n" + REQUEST_PATH + "\n" + QUERY_STRING + "\n" +
HexEncode(SHA512(REQUEST_BODY)) + "\n" + TIMESTAMP
```

簽名路徑必須包含 `/api/v4/broker/event_contracts`，例如 `/api/v4/broker/event_contracts/orders`。Query 參數順序與實際 URL 一致；Body 摘要依實際傳送的位元組計算。`sub_user_wallet_addr` 為獨立 Header，不加入 HTTP 簽名原文。演算法詳見 [Gate APIv4 認證規則](https://www.gate.com/docs/developers/apiv4/zh_CN/#%E8%AE%A4%E8%AF%81)。

## 請求範例

呼叫持倉列表時，先以 `/api/v4/broker/event_contracts/positions` 和實際 Query String 計算 `SIGN`，再傳送：

```bash
curl -i --request GET "${BASE_URL}/api/v4/broker/event_contracts/positions" \
  --header "KEY: ${BROKER_API_KEY}" \
  --header "SIGN: ${SIGN}" \
  --header "Timestamp: ${TIMESTAMP}" \
  --header "sub_user_wallet_addr: ${WALLET}" \
  --header 'Accept: application/json'
```

<Warning>
  Secret Key 僅能存放在可信服務端，不要放入瀏覽器程式碼、日誌或客服請求。
</Warning>
