公開行情頻道無須認證。訂閱私有頻道時，Broker 使用專用的 `broker_api_key` 認證方式，並在 `auth.wallet_address` 提供目標終端使用者的錢包地址。認證服務會校驗錢包與該 Broker 的綁定關係，私有訊息才會以對應使用者身分訂閱。

## 簽名

請求中的 `t` 為 Unix 毫秒時間戳。簽名原文的 `time` 使用 `floor(t / 1000)` 秒，錢包地址依 URL Query 規則編碼，並保持下列欄位順序：

```text
channel=pred.orders&event=subscribe&time=<Unix秒>&wallet_address=<URL編碼的錢包地址>
```

使用 Broker API Secret 計算 `HexEncode(HMAC_SHA512(Secret, UTF8(簽名原文)))`。WebSocket 簽名**包含**錢包地址，與 REST 請求簽名不同。不要傳送 API Secret。

## 私有訂閱範例

```json
{
  "t": 1720000000123,
  "id": "broker-private-1",
  "op": "subscribe",
  "ch": "pred.orders",
  "payload": {"all": true},
  "auth": {
    "method": "broker_api_key",
    "key": "YOUR_BROKER_API_KEY",
    "sign": "HEX_SIGNATURE",
    "wallet_address": "<USER_WALLET>"
  }
}
```

此範例簽名中的 `time` 為 `1720000000`。簽名與請求必須使用相同錢包地址；切換頻道時重新簽名。Broker REST 的 Header 與簽名規則請見[Broker API 認證與簽名](../api/broker-authentication)。
