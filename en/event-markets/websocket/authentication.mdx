Public market-data channels do not require authentication. For private channels, use the dedicated `broker_api_key` method and include the target end-user wallet in `auth.wallet_address`. The wallet must be linked to the Broker identified by the Key.

## Signature

The request field `t` is Unix time in milliseconds. Use `floor(t / 1000)` seconds in the signature string, URL-query encode the wallet address, and keep the following field order:

```text
channel=pred.orders&event=subscribe&time=<Unix seconds>&wallet_address=<URL-encoded wallet>
```

Compute `HexEncode(HMAC_SHA512(Broker API Secret, UTF8(signature string)))`. Unlike REST request signing, the WebSocket signature **includes** the wallet address. Never send the Secret Key.

## Private subscription example

```json
{
  "t": 1720000000123,
  "id": "broker-private-1",
  "op": "subscribe",
  "ch": "pred.orders",
  "payload": {"all": true},
  "auth": {
    "method": "broker_api_key",
    "key": "YOUR_BROKER_API_KEY",
    "sign": "HEX_SIGNATURE",
    "wallet_address": "<USER_WALLET>"
  }
}
```

The signed `time` is `1720000000` for this example. Use the same wallet address in the signature and payload; regenerate the signature when the channel changes. See [Broker API authentication](../api/broker-authentication) for REST request headers and signing.
