---
title: "Broker API Authentication"
description: "Use a Broker API Key to call private Event Contracts REST endpoints for users linked to your Broker."
---

Public market-data endpoints remain under `/api/v4/event_contracts/...` and do not require a Broker API Key. To perform private order, position, or account operations for a linked user, use `/api/v4/broker/event_contracts/...` and provide the user's wallet address.

## Broker API Key

Obtain a Broker API Key through the Broker management process and enable the corresponding Event Contracts permissions. Read operations require read or read/write permission; writes require read/write permission. Store the issued `Key` and `Secret Key` securely. An end user's personal API Key cannot be used in place of a Broker API Key.

| Header | Requirement |
| --- | --- |
| `KEY` | Broker API Key |
| `Timestamp` | Current Unix time in seconds, within 60 seconds of gateway time |
| `SIGN` | Hex HMAC-SHA512 signature generated with the Secret Key |
| `sub_user_wallet_addr` | Target end-user wallet; required for every private Broker REST endpoint in this section |

The gateway identifies the Broker from the Key and verifies that the wallet is linked to that Broker. Only then does it forward the request in the linked user's context. Requests with an unlinked wallet are rejected. Do not send user IDs or gateway-internal identity headers from the client.

## HTTP signature

Join the uppercase HTTP method, external request path, actual query string, SHA512 hex digest of the exact request body, and `Timestamp` with newline characters. Use an empty query string when absent and hash the empty string when there is no body. Then compute `SIGN = HexEncode(HMAC_SHA512(Secret Key, signature string))`.

```text
HTTP_METHOD + "\n" + REQUEST_PATH + "\n" + QUERY_STRING + "\n" +
HexEncode(SHA512(REQUEST_BODY)) + "\n" + TIMESTAMP
```

Sign the external `/api/v4/broker/event_contracts/...` path, such as `/api/v4/broker/event_contracts/orders`. Keep query parameter order and body bytes identical to the sent request. The wallet header is separate from the HTTP signature string. See [Gate APIv4 authentication](https://www.gate.com/docs/developers/apiv4/zh_CN/#%E8%AE%A4%E8%AF%81) for the signing algorithm.

## Example

For a positions request, calculate `SIGN` using `/api/v4/broker/event_contracts/positions` and the actual query string, then send:

```bash
curl -i --request GET "${BASE_URL}/api/v4/broker/event_contracts/positions" \
  --header "KEY: ${BROKER_API_KEY}" \
  --header "SIGN: ${SIGN}" \
  --header "Timestamp: ${TIMESTAMP}" \
  --header "sub_user_wallet_addr: ${WALLET}" \
  --header 'Accept: application/json'
```

<Warning>
  Keep the Secret Key on a trusted server. Do not include it in browser code, logs, or support requests.
</Warning>
