## Base URL

```text
https://api.dexbuilder.com
```

## REST 路由与身份

| 类型 | 路径前缀 |
| --- | --- |
| 公开行情路径 | `/api/v4/event_contracts` |
| Broker 代用户路径 | `/api/v4/broker/event_contracts` |

公开市场数据继续使用原路径，无需 Broker Key；订单、持仓、账户及结算等私有接口使用 Broker 路径。私有请求必须携带 Broker API Key、签名和 `sub_user_wallet_addr`，网关核验钱包属于当前 Broker。 详见[Broker API 认证与签名](/zh/event-contracts/api/broker-authentication)。

## 接口访问模型

| 接口类型 | 是否需要认证 | 典型能力 |
| --- | --- | --- |
| 市场发现 | 否 | 事件、市场、标签 |
| 市场数据 | 否 | 价格、Ticker、订单簿、历史数据、K 线 |
| 交易 | 是 | 下单、查询订单、撤单 |
| 账户 | 是 | 持仓、资产、余额、费率、个人成交 |
| 结算 | 是 | 平仓、领取、资金处理 |

## 分页

列表接口使用游标分页，返回 `items` 与 `next_cursor`。下一页请求直接使用上一页返回的 `next_cursor`，不要自行解析或修改游标。

## 时间与数值约定

- 事件与市场日期字段通常使用 Unix 秒；
- `from`、`to` 等范围参数通常使用 Unix 毫秒；
- 价格、数量、成交额、余额、手续费等金额类字段通常以字符串返回，建议使用 Decimal 精度处理。

## 标准错误

```json
{"label":"INVALID_ARGUMENT","message":"invalid request"}
```

常见 HTTP 状态包括 `400`、`401`、`404` 和 `503`。
