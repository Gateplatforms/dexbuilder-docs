DexBuilder 平台 API 提供资产配置、终端用户查询、Vault 余额，以及链上充值与提现能力。入驻申请接口不在本节范围内。

## 接入地址

生产环境 Base URL：

```text
https://api.dexbuilder.com
```

接口路径以 `/api/v4/dexbuilder` 开头，例如 `GET /api/v4/dexbuilder/assets`。

使用 Broker API Key 调用。签名规则见[Broker API Key 与签名](/api-reference/common/broker-authentication)；用户级接口须按[代表用户访问](/api-reference/common/sub-user-wallet)提供 `sub_user_wallet_addr`。平台权限和各类接口的钱包要求见[平台 API 认证](/api-reference/dexbuilder/authentication)。

## 接口分类

| 分类 | 能力 |
| --- | --- |
| 资产配置 | 查询资产、网络、充提开关、固定手续费和提现限额 |
| 用户 | 查询用户信息、已绑定钱包、Vault 可用余额和资金统计 |
| 充值 | 估算手续费、获取签名数据、提交交易回执、查询状态与历史 |
| 提现 | 获取签名数据、提交提现、查询状态与历史、处理 Solana ATA |

资产配置接口不需要终端用户钱包；其余用户、充值和提现接口需要 `sub_user_wallet_addr`。部分接口还需要 `x-perp-device-type` 或 `Idempotency-Key`，以对应接口的参数表为准。

## 响应与错误

成功时返回 `code`、`message`、`data`、`trace_id` 等字段；`code=0` 表示业务成功。`data` 的结构见各接口的 OpenAPI 响应模型。

错误时可能增加机器可读的 `label`。部分下游业务或风控错误仍使用 HTTP 200，因此应同时检查 `code` 或 `label`。常见业务错误如下；签名与权限失败见统一网关认证说明。

| HTTP | `label` | 含义 |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT`、`MISSING_REQUIRED_HEADER` | 参数或必填请求头无效 |
| 400 | `USER_NOT_FOUND`、`INVALID_ADDRESS` | 用户或钱包地址无效 |
| 400 | `INVALID_DEVICE_TYPE` | 设备类型缺失或取值无效 |
| 403 | `PROJECT_ACCESS_DENIED`、`PRODUCT_DISABLED` | 项目访问或产品权限被拒绝 |
| 200 | `BUSINESS_ERROR`、`RISK_CONTROL_REJECTED` | 下游业务处理或风控拒绝；查看 `message` |

充值和提现的提交接口返回“已受理”不代表链上终态。请使用相应状态查询接口确认结果。
